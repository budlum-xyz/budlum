# Finding ledger

The single finding register. Directive section 14 defines it and section 14.1
rule 9 sends every finding found while working to this file, from `BLG-268`
onward. The ledger is English because the repository is English
(`tree_is_english`).

## Rules

1. **Identity.** Every finding carries a `BLG-NNN` id. An id never changes and
   is never given to another finding.
2. **Severity.** Critical, High, Medium or Low. For a finding carried over from
   the older registers, this is the severity that register gave it; for a new
   finding the directive sets it.
3. **Status.** `open`, `confirmed` (open and reproduced), `closed` (the fix
   merged), `closed by removal` (the code is gone), `invalid` (the condition no
   longer exists, with evidence).
4. **Live verification.** WP-01 to WP-04 re-establish every finding's status on
   the live branch; the output is `docs/audit/LIVE_STATUS.md`.
5. **Closing protocol.**
   1. The agent writes the test the finding's `required test` field names. If
      the finding has none, the agent chooses a test name and writes it here.
   2. The test is red before the fix, and the pull request description carries
      the red output (S-3).
   3. The agent writes the fix and the test turns green.
   4. The pull request merges. The status becomes `closed`, and the row carries
      the commit SHA and the CI run number. A row without both is not closed.
6. **Closing by removal.** When every location of the finding is deleted the
   status is `closed by removal`. Evidence: the green output of the
   `no_legacy_storage` gate and the file list it prints.
7. **Invalidity.** If the analysis baseline already fixed the finding, the
   agent shows it with a test, the test stays in the tree, and the row is
   `closed` with the note `already fixed`.
8. **The launch rule.** No Critical or High finding stays open at the testnet
   launch. A finding that cannot close by then has its feature switched off on
   testnet and an `<feature>_is_closed_on_testnet` test proves it.

## Status of this ledger

Every finding the directive's section 14 lists is registered here: 267 rows,
`BLG-001` to `BLG-267`. Each row carries the severity, the area and the
English title the directive gives it, and the package that owns its closure.

No row is `closed` in this first version. That is deliberate and it is the
honest state: the directive's snapshot puts most of these findings open, the
reproduction tests of WP-01 to WP-04 have not all run on this tree, and a
`closed` row must carry a commit SHA and a CI run number (rule 5 item 4). A
row marked closed on the strength of a reading of the code would be a
self-report, and self-report is not evidence (section 0.3 item 5).

The one row the older register itself marks closed, `BLG-005`, is recorded as
`reported closed` rather than `closed`: the register says closed, this tree has
not reproduced it, and rule 4 hands that verdict to WP-01 to WP-04.
