# Storage measurements

The record of every storage number this tree claims, the code that produces it and
whether that code has run in Rust yet.

A number is only a measurement when a command produces it. Where the only number
available is a prototype's, this document says so on the same line as the number,
because a prototype figure quoted without its provenance reads as a Rust
measurement a reader can no longer check.

| Marker | Meaning |
|---|---|
| **measured** | produced by the named command in this tree, on this commit |
| **derived** | arithmetic over constants in this tree; no run needed, and the arithmetic is shown |
| **prototype** | produced outside this tree, by the harness named; not yet re-measured in Rust |

Run every command from the repository root.

## AR-03: the shared compression context (Section 6.20, Ek D row AR-03)

The directive's Ek D row carries a laboratory prototype, and its opening condition
is that "the Rust implementation re-measures the values". WP-54 owns that. This
section is the record the card's completion criterion asks for, and every row
below states which of the three markers applies.

### What the prototype measured

Source: `THE_BUDLUM_DIREKTIF.md`, Ek D, row AR-03. The harness was JavaScript, single
core, and it is not in this tree; the numbers are transcribed, not re-derived.

| Quantity | Prototype value | Marker |
|---|---|---|
| QR layer overhead, 1 MiB content | 11 bytes | prototype |
| Frame library match, new content | 0 of 48 | prototype |
| Fragment library match, new content | 0 of 70 | prototype |
| Selector ratio, 26 new files of one type, compression only | 0.637 | prototype |
| Selector ratio, new versions of content already in the network | 0.026 | prototype |
| Selector ratio, 16 MiB Python context | 0.573 | prototype |
| Context snapshot size (compressed) | 61 MB | prototype |
| Corpus build time | ~73 s | prototype |

Two of those rows decide a design and must not be lost in the transcription:

* **The frame and fragment libraries are eliminated.** 0 of 48 and 0 of 70 matches on
  new content is a library that never fires on the traffic it was built for. Nothing
  in `src/storage/bud3` implements one, and this record is the reason.
* **The selector beats compression alone on 26 same-type files (0.637) but barely
  fires on new versions (0.026).** The context pays when an uploader holds a corpus of
  one class, which is what Section 6.20 item 2.2 describes, and not when it holds a
  single earlier version.

### What this tree can state without a run

These are arithmetic over constants the code carries, so they are checkable by
reading, and they are marked **derived** rather than measured.

| Quantity | Value | Where the arithmetic comes from |
|---|---|---|
| BOF-1 header, no optional field | 38-45 bytes for a public object with a one-byte varint profile, codec and dictionary | **derived**: `2 + 1 + 1` magic and version and flags, three varints, `content_len` varint, 32-byte content digest, `payload_len` varint (`src/storage/bud3/bof1.rs`, `Header::encoded_len`) |
| BOF-1 header, context-coded object | the above plus 32 bytes for `context_manifest` | **derived**: same function, `Flags::HAS_CONTEXT` branch |
| BOF-1 header, live segment | the public header plus 32 bytes for `prev_object` | **derived**: same function, `Flags::LIVE` branch |
| Largest object for a 1 MiB content | content + header + payload-length digits | **derived**: T9 in Section 6.23 is the bound the object must satisfy |

The QR-layer overhead the prototype measured (11 bytes per MiB) is the frame and
symbol layer, which is `src/storage/bud3/frames.rs` and `src/storage/bud3/object.rs`.
Its Rust value is **not yet measured**; see the section below.

### What has to run, and has not yet

Re-measuring AR-03 in Rust needs a harness that (1) builds an object for a 1 MiB
content of each class and reports the byte length above the content, (2) runs
`budlum_codec::select` over 26 files of one class and reports
`sum(payload) / sum(content)`, (3) runs the same over 26 successive versions of one
file, and (4) runs the selector over a 16 MiB corpus of one language and reports the
total ratio. Every input it needs is generated by the harness itself, so the corpus
is not committed and the number is reproducible from the command alone.

Until that harness exists and runs, the rows above stay marked **prototype**. This
document does not promote them, and the WP-54 completion criterion is therefore met
for the context and dedup code and open for the AR-03 re-measurement.
